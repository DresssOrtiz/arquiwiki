# ISO/IEC/IEEE 42010 (descripción de arquitectura), resumen propio

> Resumen con palabras propias, hecho para orientar. La norma tiene derechos de autor: cotejar con el texto oficial.

La norma no dicta cómo diseñar: dicta qué debe contener una **descripción de arquitectura (AD)** para que sea comprensible y auditable. Su idea central: la arquitectura se describe mediante vistas que responden a las preocupaciones de los interesados.

## Elementos clave
| Elemento | Qué es | Cómo buscarlo en los artefactos |
|---|---|---|
| Entidad de interés | El sistema cuya arquitectura se describe | nombre del sistema en el DSL y en `requisito.md` |
| Stakeholders | Quienes tienen interés en el sistema (usuarios, operadores, equipo, docente) | lista explícita o personas del DSL |
| Preocupaciones (concerns) | Lo que a los stakeholders les importa (rendimiento, seguridad, costo) | atributos de calidad del requisito, `decisiones.md` |
| Puntos de vista (viewpoints) | Convenciones para construir un tipo de vista: qué preocupaciones cubre, qué notación usa | C4 (contexto, contenedores, componentes), UML (paquetes, secuencia) |
| Vistas (views) | Aplicación de un punto de vista al sistema concreto | cada vista de `modelo.dsl`, `paquetes.puml`, `secuencia.puml` |
| Tipos de modelo | Las clases de modelo que usa el punto de vista | diagrama de contenedores, diagrama de secuencia |
| Correspondencias | Relaciones declaradas entre vistas o elementos (mismo elemento en dos vistas) | nombres coherentes entre DSL y UML; tabla explícita |
| Justificación (rationale) | Por qué se tomó cada decisión, alternativas y consecuencias | `decisiones.md` con cita |
| Conformidad | Que la AD cubra todas las preocupaciones con alguna vista | cada preocupación apunta a al menos una vista |

## Pruebas rápidas
1. ¿Cada preocupación listada está cubierta por al menos una vista? (si no, brecha)
2. ¿Cada vista declara su punto de vista (qué notación y para quién)? (en C4 y UML basta una línea)
3. ¿Hay correspondencias explícitas, o solo coincidencia de nombres?
4. ¿Cada decisión relevante tiene justificación y alternativa descartada?
5. ¿Hay stakeholders nombrados, no solo "el usuario"?

## Veredicto sugerido por elemento
Presente (evidencia citada), Parcial (implícito o incompleto), Ausente.
