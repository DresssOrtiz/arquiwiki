# ISO/IEC 25010 (modelo de calidad del producto), resumen propio

> Resumen con palabras propias, hecho para orientar. La norma es una publicación con derechos de autor: cotejar siempre con el texto oficial. Esta referencia sigue la revisión de 2023; la de 2011 tenía ocho características (usabilidad y portabilidad pasaron a ser capacidad de interacción y flexibilidad; se añadió protección/safety).

El modelo describe nueve características de calidad del producto de software, cada una con subcaracterísticas.

| Característica | Pregunta guía | Subcaracterísticas (orientativo) |
|---|---|---|
| Idoneidad funcional | ¿Hace lo que debe, bien y de forma apropiada? | completitud, corrección, pertinencia funcional |
| Eficiencia de desempeño | ¿Responde a tiempo y con recursos razonables? | comportamiento temporal, uso de recursos, capacidad |
| Compatibilidad | ¿Convive e intercambia información con otros sistemas? | coexistencia, interoperabilidad |
| Capacidad de interacción | ¿Las personas lo usan con eficacia y sin errores? | reconocibilidad de la idoneidad, facilidad de aprendizaje, operabilidad, protección ante errores del usuario, compromiso del usuario, inclusividad, asistencia al usuario, autodescriptividad |
| Fiabilidad | ¿Funciona de forma consistente y se recupera de fallos? | ausencia de fallos, disponibilidad, tolerancia a fallos, recuperabilidad |
| Seguridad | ¿Protege datos y accesos? | confidencialidad, integridad, no repudio, responsabilidad (trazabilidad de acciones), autenticidad, resistencia |
| Mantenibilidad | ¿Es fácil de analizar, cambiar y probar? | modularidad, reutilización, analizabilidad, modificabilidad, capacidad de prueba |
| Flexibilidad | ¿Se adapta a otros entornos y crece o se reemplaza con facilidad? | adaptabilidad, escalabilidad, instalabilidad, reemplazabilidad |
| Protección (safety) | ¿Evita daño a personas, bienes o entorno? | restricción operativa, identificación de riesgos, falla segura, aviso de peligros, integración segura |

## Cómo usarla en la evaluación
1. Para cada característica decide si el requisito la toca de forma directa, indirecta o no la toca.
2. Si la toca, busca en los criterios de aceptación un escenario que la haga verificable con una medida.
3. Registra la brecha cuando no hay escenario o la medida es vaga.

## Equivalencia con la versión 2011 (para apuntes antiguos)
Adecuación funcional = idoneidad funcional; usabilidad ≈ capacidad de interacción; portabilidad ≈ flexibilidad; protección es nueva.

## Pistas de verificabilidad por característica
- Desempeño: percentil de tiempo, carga, volumen de datos.
- Fiabilidad: porcentaje de disponibilidad, tiempo de recuperación.
- Seguridad: umbral de intentos, roles permitidos, evento auditado.
- Mantenibilidad: criterios sobre estructura y pruebas, no sobre el comportamiento visible.
